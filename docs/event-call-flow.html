Calling an event in ChimeraMapR

Every event class the pipeline reports comes out of one pass over a chromosome's LOH chain, where a fixed tract is tested against fourteen rules in a fixed priority order. This is what each of those gates actually asks — and where a tract goes when none of them can answer.

The one question four rules share

Why priority order is the decision

The scan is not a left-to-right cursor where whichever rule reaches a peak first keeps it. Every rule proposes everywhere, and a single selector then settles the contests — so the outcome depends on an inspectable objective rather than on the order the chain happened to be walked.

R11 and R12 share a motif

Both are an interstitial tract with a peak on each junction. What separates them is what the peaks say: R12 needs a pair record typed crossover that genuinely straddles this tract, R11 takes two peaks that only classify as binary. R12 runs first so a real crossover pair is never re-read as an unresolved binary pair.

Why R11d comes before the peak rules

The peak rules classify a tract from junction peaks whose zones are bounded by neighbouring peaks, not by heterozygosity. On a run of tracts with no callable HET between them, those zones fall inside fixed sequence — and the rule reads the LOH map back to itself as if it were phase.

What a deletion has to survive

Depth alone is a knife-edge proxy: 0.601 against a 0.60 threshold once cost a real 1.6 kb deletion its call. Read-level evidence is the second, independent trigger, and the count reported as n_support is the reads that register the deletion — reported only when that trigger fired, since a long deletion removes its reads entirely.

Disabled rules

R04 (HET-bounded) was replaced by R10 and R11. R02b (peakless terminal, HET abutting F) is off because a missing peak there is not positive evidence of anything — R02d handles the case where a wide gap explains the absence. R07–R09 remain disabled pending redesign.

What never becomes an event

Unclaimed LOH tracts

A fixed tract no rule claimed has no positive evidence for any mechanism, so it is not promoted into the events table at all. It appears once, in Other events, annotated with why — no attached peak, or too few SNPs to raise one.

Unclaimed peaks

A peak that never attached to a token is run through the same classifier the rules use. If it resolves it becomes a _subres event, scored high at or above min_span reads. If it does not — binary singleton, independent reads, no edge type — it stays in Other events with the reason attached.

Nothing is reported twice

An interval is either a called event or an unclaimed one, never both. Fused peaks are collapsed to one row per fusion group first, so a gene-conversion pair does not surface as two identical calls differing only in read count.

Ambiguity is not promoted

An AMBIGUOUS call keeps its reason in the notes and always scores review, however many reads sit behind it. Plenty of evidence for an unresolved question is still an unresolved question.
